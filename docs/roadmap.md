# Roadmap：FluMonitor 分阶段执行路线

> 本文档回答"按什么里程碑推进、每站交付什么、哪里可以停"。决策细节见 [CONTEXT.md](../CONTEXT.md)，技术设计见 [design.md](design.md)，任务拆解见 `.trellis/tasks/`。本文档只补"里程碑/停靠点"视角，不重复上述内容。

## 原则（为什么这样分）

1. **每个里程碑结束都有一个能验证、能停下、能给你看的东西**——分阶段的唯一目的，不是仪式。
2. **纵切不横切**：优先让"一条窄线从头通到尾"，而不是"先写完所有抓取再写所有计算"。横切会把集成风险憋到最后才爆。
3. **风险前置**：最不确定的事放最前面（数据能不能支撑产品），别等写了大量代码才撞墙。
4. **诚实性是核心不是装饰**：工具要会说"我不知道"（缺失/过期显式提示），这是辅助防护决策工具的底线，不推迟到最后做。
5. **你随时能停**：每个 M 结束是一个决策点，你看过交付物再决定是否继续。

## 通用参照：成熟工具的 6 个阶段

| 阶段 | 做什么 | 交付（验证物） |
|---|---|---|
| 0 需求与设计 | 澄清要什么/不要什么/关键决策 | 设计共识 + 任务分解 |
| 1 可行性验证 | 证明最大未知能成立 | 可行性结论 |
| 2 最小闭环 | 最少代码让输入→处理→输出跑通一次 | 一个能看的最小成品 |
| 3 健壮与诚实 | 处理失败/缺失/过期/边界 | 不骗人、不崩的版本 |
| 4 自动化与交付 | 定时/部署/分享/说明 | 别人和未来的你能独立用 |
| 5 迭代扩展 | 加功能/数据/地区/美化 | 持续增强 |

## FluMonitor 的里程碑（纵切）

> 阶段 0 已完成（grill + D1–D19 + CONTEXT/design/ADR）。阶段 3「健壮与诚实」不单列里程碑——其要求已分散进各任务 PRD 的验收标准（数据状态、缺失不默认绿、过期提示），实施时不得跳过。

### M1 可行性验证
- **任务**：`11-06-data-feasibility`
- **做**：只读小样本，证明各源字段/口径/可比性成立，验四川图片识别可行性、GitHub 境外 runner 对 chinacdc.cn 连通性。
- **交付**：口径对照表 + "可行/需降级/不可行"结论。
- **停靠点**：看结论，决定 data-fetch 的回补范围与口径；此处叫停成本最低。

### M2 最小闭环（只做流感一条线）
- **任务**：`data-fetch`(仅流感源) → `compute-index`(仅 Goldstein) → `build-site`(仅阶段一极简分块页)
- **做**：抓国家流感中心南方片 → 算 Goldstein 指数 → 极简分块页先只有「南方片流感块」+「四川分级块」(占位/手填)，本地能打开看到真实最新一周。
- **交付**：第一个真能用、有真实数据的成品页。
- **停靠点**：这是你（非开发者）最重要的信心节点——第一次看到成品。看过再决定是否补全。

### M3 补全数据（拆为 M3a 数据层 / M3b 展示层）

> 2026-11-09 据 metis 缺口分析拆分：数据工程与前端是两种规模的工作包，分层各自可验收。同期对比降级为"先文字差值"（流感周报 PDF 正文已含往年同期数值，零回补）；四川识别降为半自动辅助（独立脚本无多模态调用链，D19 落地为抓图+人工输入等级）。

**M3a 数据层**
- **做**：中疾控哨点周报表1全国11病原阳性率（门急诊/住院+较上周）、表2/表3南北与年龄组前三名（名称排序，支持并列）、WHO FluNet 中国全量（按列映射）、哨点周报历史回补（约100期，验证分页机制）。继承 M2 的 r3 写入契约与状态文案枚举。
- **交付**：多病原/排序/FluNet CSV 齐全，可验收"数据齐了"。
- **停靠点**：数据层完成，可先验收再进 M3b。

**M3b 展示层**
- **做**：阶段二仪表盘——风险卡 + 流感/新冠/RSV 本周阳性率与环比 + 多病原活跃度排行 + 儿童分龄前三卡 + 本周vs往年同期**文字差值**（非曲线）。仍分块不合成总分，方式A内联+file://离线。趋势图渲染方案在 M3b 规划时定（内联SVG/极简Canvas，不引外部库）。
- **交付**：五块证据齐全的分块仪表盘页。
- **停靠点**：日常自用此时已足够。

**缓做工作包（主体验收后按需）**
- 流感周报多年历史回补（约150期PDF）→ 多年同期对比曲线（替换文字差值）
- 四川 update_sichuan 半自动脚本（抓图+打开+人工输入+写CSV+可选推送）——亦可并入 M4

### M4 自动化与交付（拆为 M4a 本地改造 / M4b 云端首跑）

> 2026-11-09 据 metis 缺口分析拆分：跨平台改造本地可验证，云端首跑依赖外部网络（境外 runner 对 chinacdc.cn 连通性=全项目最大未验证风险）+ 需用户在 GitHub 网页做一次性操作，分层各自可验收。三决策（用户 2026-11-09）：runner 不通兜底=本地抓+云端发布；四川识别=update_sichuan 纯本地输入零API；M4 拆 M4a/M4b。

**M4a 跨平台改造 + 依赖标准化（本地可验，不需 GitHub 网页操作）**
- 建 `requirements.txt`（beautifulsoup4 等）；`fetch_flu_south.py` 的 pdftotext 路径跨平台（Windows 绝对路径 + `shutil.which` 兜底）
- `run_local.bat` 行为明确（写 data/ 不自动 push，README 说清）
- `update_sichuan.bat`〔D19〕：纯本地交互——抓当月四川图片+自动打开+命令行输入等级(I-V)+写 sichuan_monthly.csv+可选推送，零 API 零依赖
- `.gitattributes` 加 `data/*.csv text eol=lf`（避免跨平台行尾巨 diff）
- 发布前核查 checklist（仓库文件逐条是否公开，脱敏个人信息）
- **交付**：本地全链路跑通、跨平台就绪、update_sichuan 可用。**停靠点**：本地可验收，再进 M4b。

**M4b 云端 Actions 首跑（需用户在 GitHub 网页操作）**
- `.github/workflows/weekly.yml`：周五定时（cron UTC 换算，推荐 UTC02:00 周六=北京10:00 周五）+ workflow_dispatch 手动；步骤含 `apt-get install poppler-utils` + `pip install -r requirements.txt` + 连通性探测（`curl -I chinacdc.cn` 打印状态不阻断）+ 抓数(失败不阻断,兜底用仓库已有CSV) + 算指数 + 构建 + artifact 部署 Pages
- 用户一次性网页操作：①Settings→Pages→Source 选 "GitHub Actions" ②Actions→Run workflow 首次手动触发
- 首跑验证境外 runner 对 chinacdc.cn 连通性；不通则启用兜底（本地抓+推送，云端只构建部署）
- **交付**：Pages 链接可访问、每周自动更新（或兜底模式）。**停靠点**："做完了"。

### M5 按需扩展（可长期不做）
