# ADR-0001：采用 GitHub Actions 双触发架构，而非 WorkBuddy 或纯本地方案

- 状态：已接受
- 日期：2026-11-06
- 决策者：用户（现居成都，自述无开发经验）+ AI

## 背景

用户要做一个个人用传染病监测工具，首要用途是日常出行防护参考，可分享给家人。约束：用户无开发经验、希望近零运维、工具价值依赖**每周持续产生数据**（往年同期对比是核心）。参考对象是一个用腾讯 WorkBuddy 生成、带 sharecode 分享链接的流感指数面板。

候选方案：
- **WorkBuddy**：对话生成网页应用、一键发布得分享链接，与参考面板同款。
- **GitHub Actions + Pages**：云端定时跑脚本 + 静态网页托管。
- **纯本地脚本**：本地双击运行，生成本地 HTML。

## 决策

采用 **GitHub Actions + GitHub Pages 云端自动更新**（方案 a）**叠加本地双击脚本**（方案 b）的双触发架构：同一套 Python 抓取/计算代码，云端由 Actions 每周调用、本地由用户双击调用，历史数据以 CSV 存于仓库、两端共享。放弃 WorkBuddy。

## 理由

1. **WorkBuddy 的定时自动化是本机执行**（官方文档实测：需执行时电脑开机不休眠）——无法满足"无人值守每周更新"，而这恰是工具价值的命脉。其生成逻辑为黑盒，无法精确控制成都三层拼合与口径标注。免费额度每月 100 积分是否够用未验证。
2. **GitHub Actions + Pages 公共仓库完全免费**（官方文档）、cron 定时、WHO FluNet CSV 与 chinacdc.cn 均实测可匿名读取当期页面。注意（2026-11-06 修正）：页面可匿名访问不等于授权高频抓取或公开再分发；回补须礼貌限速，发布前核资料使用条件。Pages 发布走自定义 Actions artifact 部署（GITHUB_TOKEN 提交不触发构建，分支发布目录仅限根/docs）。
3. **用户 GitHub 环境已就绪**（实测：gh 已登录 Zengwenj，token 含 repo/workflow 权限），接入零额外授权成本。
4. **叠加本地触发几乎免费**：核心代码只写一次，本地只是另一个调用入口，为云端故障提供备份、满足即时查看与"数据在自己手里"的掌控感。

## 代价与权衡

- 需用户持有公开 GitHub 仓库（数据与代码公开——但均为公开监测数据与公开算法，无隐私风险）。
- 需编写 workflow + 抓取脚本（由 AI 承担，用户不接触代码）。
- 公共仓库 60 天无提交会暂停定时任务（每周有数据提交即自动续，基本不触发）。
- 本地入口需用户一次性安装 Python 运行环境。

## 未验证项

GitHub 免费层是否需信用卡、WHO 端点限流阈值、chinacdc.cn 深层反爬行为——均在实现阶段首次真实运行时验证。
