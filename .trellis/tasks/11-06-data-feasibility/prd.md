# PRD：数据可行性验证（子任务 0/5，前置）

> D18 新增（2026-11-06 评审修订）。本任务是整条管线的真正起点，先于 data-fetch。目的：在写大量抓取/回补代码前，证明"官方数据真的能支撑设计的产品"，避免做完一堆才发现口径对不上。

依赖：无。下游：data-fetch（本任务结论决定其回补范围与口径）。

## 要做什么

对每个数据源做小样本只读验证，产出"口径对照表 + 可行性结论"：

1. **中疾控哨点周报**：确认表1=全国 11 病原阳性率数值（门急诊/住院）、表2=南北前三名、表3=各年龄组前三名（名称非数值）。取最近 2-3 期 + 抽查 2024/2025 各 1-2 期历史，确认版式一致、可解析。
2. **国家流感中心流感周报**：确认南方片 ILI%、流感阳性率的**数值**是在 HTML 还是 PDF；能否拿到过去 1-3 年同口径南方片序列（供 D17 同期对比曲线）。若仅 PDF/图片难解析，记录并定首期替代（退到哨点周报全国口径）。
3. **四川省流感指数（图片）**：验 OCR + 多模态模型双通道识别五级分级的可行性与一致性；定义置信度不足时的"待人工确认"判定。**识别按 D19 走本地半自动**（每月一次本地执行 + 用户确认），本阶段只需验证"识别技术可行 + 一致性达标"，不验证云端 API 调用。
4. **WHO FluNet CSV**：确认中国流感字段、周粒度、匿名可下载（作全国背景，非南方片指数输入）。
5. **GitHub 境外 runner 连通性**：验证 Actions runner（境外 IP）能否访问 chinacdc.cn；不通则记录，供 deploy 定本地补抓兜底。

## 约束

- 只读、小样本、礼貌限速；不建仓、不批量回补、不写功能主代码。
- 结论区分：已核实事实 / 推测 / 待实现阶段再验。

## 验收标准（可独立验证）

- [ ] 产出口径对照表：每源的 地理粒度 / 时间粒度 / 指标是数值还是排序 / 年龄维度 / 载体格式 / 历史深度。
- [ ] 明确 Goldstein 指数的南方片两项输入（ILI%、流感阳性率）各自真实来源与历史可得性。
- [ ] 四川分级双通道识别在至少 2 个月份图片上验证一致性，并定义不一致处理。
- [ ] GitHub runner 对 chinacdc.cn 连通性有明确实测结论。
- [ ] 输出"可行/需降级/不可行"清单，data-fetch 的回补范围据此定稿。
