## 结论摘要

**不能按现 PRD 直接进 design。** 需先解决 3 个前提：
1. 失败留痕写在哪里，会与现有页面横幅冲突（GAP-1）
2. 本任务是否包含展示层改动，以及"往年同期"的呈现形式（GAP-2）
3. 回补期数口径不一致，且缺少抽样探针（GAP-3、GAP-4）

## 逐条答复（对应 PRD Open Questions）

1. **分页**：【已验证·二手】`index_N.html` 静态分页已在前序任务确认（`archive/.../11-06-data-fetch/design.md:39`），哨点同机制已实跑（`fetch_sentinel.py:62-86`）。【未核实】流感列表每页条数、能否翻到 2023 年初（M1 记列表共 933 期，`feasibility-report.md:16`）。URL 不能按规律推算——文章 ID 与 PDF 文件名都含不可预测数字（`t20261105_1842732.html`、`P020261105477887655154.pdf`）。分页走不到 2023 就是真阻塞，需交用户决定。
2. **版式兼容**：【未核实】2023/2024 的 PDF 一份没读过。已知 2025/2026 两种阳性率写法已兼容（`fetch_flu_south.py:109-127`）。失败点见 GAP-5。ILI% 与括号百分比措辞/全半角不同会抛 RuntimeError，属安全失败。失败率无法预估，需 S0 抽样探针。
3. **起点**：假设 2023W1，与 PRD 一致。2023W1→2026W44 约 **200 期**（52×3+44），不是 PRD 的约 150。M1 的 150 对应近三年（约 157 期）。按 200 期算下载约 **1.3GB**（每期 6.5MB 只测过一期）。往年同期对比时 2026 年大部分周可拿到 2023/24/25 三个点。
4. **展示层**：都不会随数据自动生效，需改 build_site。
   - 环比：逻辑已有（`build_site.py:81-85`），但取"最近更早的 ok 周"，不检查是否相邻。回补后若有缺周，会把"较上周"标在隔了好几周的数据上，违反 D17。守卫 `prev[-1:]` 还依赖 CSV 行序。
   - 往年同期：完全是占位（`build_site.py:88`、`:246-251`）。
5. **断点续跑**：默认按标题解出的周次，已有 `status=ok` 的周直接跳过、不下载。另加 `--force` 重抓并对比，有差异写 changes.log 再覆盖（依据 CONTEXT.md:71 不采纳"永不重抓"）。`upsert` 对 ok 覆盖 ok 目前不留差异日志（`fetch_flu_south.py:163-168`，对比 `fetch_sentinel.py:285-293`）。
6. **留痕**：见 GAP-1。CSV 无原因列（`fetch_flu_south.py:35-37`），原因只能写 `data/changes.log`，沿用现有 tab 分隔格式 `ts\tYYYYWn\twhich\told\tnew`（`fetch_sentinel.py:271-274`）。flu 脚本无 `log_change`，需新增。已读文件里未找到 flu_south 失败行的 status 枚举定义。
7. **缓存**：建议缓存 pdftotext 抽出的 **txt**，不缓存 PDF，放 `.tmp_flu_backfill/`（`.gitignore:2` 的 `.tmp_*/` 已覆盖）。txt 缓存让正则调试不必重复下载 1.3GB，也避开版权/体积问题。耗时【推断】40–60 分钟（M1 实测单期下载 3.2s + 2.5s 限速）。
8. **隐藏需求**：
   - ISO 周 53：2026 年有 53 周，往年同期查找要处理"无同周"
   - 2025W14–22 式月度合并版在流感周报里是否存在，【未核实】
   - 其余见 GAP-5 静默错值风险
9. **weekly.yml**：不需改。云端只跑无参 `fetch_latest`（`weekly.yml:60-64`）。新增 `--backfill` 必须放在 `__main__` 里"任何参数都当 URL"的分支之前（`fetch_flu_south.py:202`），否则会被当 URL。运维隐患：本地回补整表重写 vs bot 每周五追加 `data/`（`weekly.yml:80-90`），文件尾部可能冲突——回补推送要避开周五并先 `git pull`。

## 问题清单

### BLOCKER（已核实）

**GAP-1 失败行与页面横幅冲突**
- 证据：`build_site.py:69-80`，任何非 ok 行只要不晚于最新 ok 周，就永久显示"最新一期解析失败 · 请人工核对官网"
- 影响：PRD 验收第 2 条若按"CSV 写失败行"实现，线上页面会常驻错误横幅
- 最小修正：失败只记 changes.log，CSV 只放 ok 行；或横幅只看晚于最新 ok 周的失败行。**推荐前者**，与哨点回补先例一致（`fetch_sentinel.py:353-354` 只打印不写行）

**GAP-2 范围与形式未定**
- 证据：占位在 `build_site.py:88`、`:246-251`；CONTEXT.md:17 把同期对比定义为叠加曲线，handoff.md:113 说叠加曲线已被 D17 废止
- 影响：验收第 4 条靠纯数据层做不到，形式有冲突
- 最小修正：用户裁决（见下）

### 重要

- **GAP-3 期数口径不一致**：约 150 期对应近三年，"2023 起"是约 200 期，需统一
- **GAP-4 缺 S0 抽样探针**：design 第一步先对 2023/24/25 每年至少抽 3 期（年初/年中/年末），用现成抽验模式 `python -X utf8 src/fetch_flu_south.py <文章URL>` 跑，写明停止条件（如多数期解析失败即停并汇报）
- **GAP-5 静默错值风险**（代码事实已核实，影响为推断）
  - 自算路径的分母正则取全文第一个"检测…份"，未限定南方（`fetch_flu_south.py:118`）。若抓到全国分母，阳性率偏低且不报错。PDF 内有"南方/北方/合计"表（`feasibility-report.md:29`），可交叉校验
  - `week_start` 兜底取全文第一个日期（`:130`），未必是周一。建议用 `date.fromisocalendar` 校验
  - 年初年末周号约定是否与 ISO 一致，【未核实】
  - PDF 内期号与列表标题期号可能不一致，写入前必须比对，不一致判失败
  - 月度合并版或同周重复发布会被静默取首周：标题含范围或 PDF 内多个期号头就判失败；同周重复时先遇到的（新发布）胜出
- **GAP-6 CSV 行序**：回补从新到旧遍历，`upsert` 是"删旧追加"，CSV 会乱序，不便 Excel 核对，还影响 `prev[-1:]`。建议回补结束后按 (year, week) 排序一次，并在 design 明确这不属于对单期模式的改动

### 次要

- `http_get` 的 curl 兜底没有 `-f`（`fetch_flu_south.py:50-54`），404 页会被当成功数据
- 回补后必须再跑 `compute_index`，goldstein 列才有值
- 2023 年初基线可能不典型，展示时不要对往年求平均，逐年分列

## 任务边界建议

拆成两个：
- **A1a（本任务）**：`--backfill` 数据层、S0 探针、changes.log 留痕、排序、回归验证
- **A1b（新子任务）**：环比相邻周检查、往年同期块

理由：同期对比形式需用户先裁决（GAP-2），不该卡住数据回补；回补一次性推送约 200 行，应先让用户在 Excel 核对。代价是两件事各过一遍评审与批准的门。

## 可采用的低风险假设

- 起点 2023W1
- 默认跳过已有 ok 周，加 `--force`
- 限速沿用 2.5s（`fetch_sentinel.py:32`）
- 缓存 txt 放 `.tmp_flu_backfill/`
- 不改 `weekly.yml`

1. S0 报告：列表最早发布日期不晚于 2023 年初；每年至少 3 期解析值与 PDF 原文人工一致

3. 覆盖对账：2023W1 至最新 ISO 周历期望周数 = ok 周数 + changes.log 有原因的失败周数 + 官网无此期的周数

5. 续跑：中途中断再跑，ok 周下载数为 0；完整状态下再跑，CSV 逐字节一致

7. 回补后跑 `compute_index`，所有 ok 行有 goldstein 且等于 ILI%×阳性率（2 位），抽 3 行核对

9. 人工抽验：2023/2024/2025/2026 每年至少 2 期，含年初/年末周

### ivdc 档案页机制（实测，影响实现细节）

- 分页：`index.htm` + `index_1.htm`…`index_29.htm`，扩展名是 **`.htm`**。
  页数由页内 JS 变量给出：`var countPage = 30;//共多少页`。
- **越界页不返回 404**：`index_30.htm` 为 HTTP 200 + 146 字节"找不到"提示页；
  `http_get` 的 curl 兜底（`src/fetch_flu_south.py:50-54`）无 `-f`，会当成功响应。
  → 必须读 `countPage`，不能靠"翻到空页为止"。
- 列表条目标题格式：`2026 第44周`（只有年+周，**没有期号**）；发布日期在同 `<li>` 的
  `<span class="span_02">(2026-11-05)</span>`。
- 文章页：`<h3>2026 第44周</h3>` + `发布时间：2026-11-05` + PDF 链接锚文本
  `2026年第44周第933期中国流感监测周报.pdf`（年/周/期齐全）。
  **但该锚文本格式不稳定**：实测 2016W10 锚文本为 `0.pdf`。
- 每期文章页只有 1 个 PDF 链接，`find_pdf_link` 现逻辑可直接复用。
- 2024W1/W1 的 PDF 实际文件名时间戳是 2026-01（上游重新上传），内容与 chinacdc 版一致。
