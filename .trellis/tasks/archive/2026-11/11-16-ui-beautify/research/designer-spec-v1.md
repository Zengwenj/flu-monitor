# FluMonitor A4 · 视觉规格（v1，供 design.md 冻结）

> 依据：`src/build_site.py:914-984`（现有 CSS）、`:987-996`（DOM 骨架）、`:397-406`（`_HIST_STYLES`）、`:764`（`_card`）、`:1075-1083`（`_sc_body`）、`:1545-1570`（搜索骨架）、`:1752-1755`（默认卡序）。所有色值对比度为本机实算（WCAG 2.1 相对亮度公式），非估计。

## 1. 设计概念与命名

**「检验单」（Clinical Readout）** —— 一份可核查的检验报告单，而不是一台仪表盘。

三条视觉法则来自这个概念本身：

1. **纸是白的，线是发丝的，编号是等宽的。** 数据靠位置和对齐建立秩序，不靠色块和阴影。
2. **只有一个强调色（仪表青 `#0B5D6B`）。** 它标记"这是什么工具"，不标记"危险不危险"。
3. **缺测与异常是批注，不是底色。** 引用虚线框、斜纹、方括号文字——报告单上"未做"的写法，不是仪表盘上"报警"的写法。

**为什么适配这个主题**：呼吸道传染病监测页的读者在做一件很具体的事——**核对官方哪一期说了什么，以及这个工具是否漏了、错了、旧了**。他需要的是可追溯感和零夸张，不是沉浸感。检验单隐喻天然携带"样本/口径/时间戳/缺测"这些正是本项目最重的信息（D14 分块证据、D15 名称不造数、D17 箭头只表较上周）。反过来，科幻 HUD 那套发光与深底会**主动制造语义污染**：发光 = 注意我，深底 = 警戒，正好把"暂缺"读成"有情况"，直接踩诚实性红线。

## 2. 配色系统

### 2.1 解决真实矛盾：红色不能再是"风险"

把颜色拆成**两条互不干涉的轴**，这是整个方案的地基：

| 轴 | 用途 | 允许出现的位置 | 禁止 |
|---|---|---|---|
| **病种识别色**（红/灰/紫/钢蓝） | 只是"这条线是流感/新冠/RSV/南方片" | 折线与图内末端数值标注 | 任何 ≥8px 的实心填充块、卡片底色、地区评级 |
| **数据状态色**（青/琥珀/砖红/中性） | 数据是否新鲜、是否取到、是否算成功 | 状态文字、1px 左边条、极小的状态点 | 给城市或地区判"风险高低" |

**硬性护栏（写进 CSS 注释）**：
> 病种识别色不得施加于任何 background 属性；红色（`#C0392B`）在页面上的总着色面积必须 < 全页可见面积的 1%，且只以 1.6px 线宽 + 2.6px 端点出现。

这样"红=流感这条线"与"红=出事了"在视觉上被面积和形态隔开：一条 1.6px 的折线读不出警报，一个 40px 高的红底块才读得出。

**数据状态色**

第四行是关键：**"未知"是独立的第三态，中性灰 + 虚线边框**。它既不是绿（安全），也不是琥珀（待办），也不是任何一级色阶的成员——视觉上它在体系之外，正如它在证据上在体系之外。

### 2.3 五级官方分级的色阶

**单色相、单调明度、无彩色语义**：`#D8E8EB + #2F5760` → `#14505F + #FFF`。低→高 = 浅→深。

| 级 | 填充 | 级内文字 | 对比 |
|---|---|---|---|
| Ⅴ（最低） | `#D8E8EB` | `#2F5760` | 6.28 ✓ |
| Ⅳ | `#AECFD6` | `#0C3F4A` | 6.95 ✓ |
| Ⅲ | `#7FAEB9` | `#062A32` | 6.25 ✓ |
| Ⅱ | `#3D7C8B` | `#FFFFFF` | 4.71 ✓ |
| Ⅰ（最高） | `#14505F` | `#FFFFFF` | 8.96 ✓ |

**为什么不用红黄绿**：①在四川这套口径里 Ⅴ 是**最低**级，红黄绿三段式会把"低风险"直接画成红色，语义完全反了；②五级是**序数**（有大小、无比例），正确编码是单调明度——就像比色卡、稀释梯度、灰度标尺，深浅即强度；③色阶同色相后，与品牌青同族，页面的"最强色"自然落在官方结论上，不需要额外强调手段。

**"未获取"必须在色阶之外**：中性底 + 虚线框，且文字固定为"官方分级未获取 · 状态未知"。绝不允许落成 Ⅴ 的空心版（那读作"低风险且待确认"）。

**前置假设（实施前须核对 CONTEXT.md 分级表）**：本方案按用户口径"Ⅴ 最低、Ⅰ 最高"编排，标尺自左向右 Ⅴ→Ⅰ 明度递增。若官方实际相反，整条色阶左右翻转即可，其余不变。

## 3. 排版系统

### 3.1 字体栈（无外部字体）

```
正文  --sans: -apple-system, "Segoe UI", "PingFang SC", "Hiragino Sans GB",
              "Microsoft YaHei UI", "Microsoft YaHei", "Noto Sans CJK SC", system-ui, sans-serif
标识  --mono: ui-monospace, "Cascadia Mono", Consolas, "SF Mono", Menlo, monospace
```

`-apple-system` 必须占首位（macOS/iOS 优先），Windows 落到 Segoe UI（拉丁）+ 微软雅黑 UI（中文）。**不设等宽字体给中文**——Consolas 无中文字形，会回退到系统默认，导致行内高度跳变，所以 mono 只用于纯 ASCII/数字标识（周次、编号、`GOLDSTEIN`、`SRC-01`）。

### 3.2 字号阶梯

| 角色 | 字号 | 字重 | 行高 | 字距 | 色 |
|---|---|---|---|---|---|
| 关键数字 `.big` | **46px**（≥720）／34px（<720） | 700 | 1.02 | -0.02em | `--ink-1` |
| 页面 h1 | 21px | 600 | 1.3 | 0.01em | `--ink-1` |
| 卡标题 `.card h2` | 13px | 600 | 1.4 | 0.02em | `--ink-2` |
| 正文字号（`.adv`/`.chain`/`.rank`/`.kv`） | 15px | 400 | 1.62 | 0 | `--ink-1` |
| 次级数值 `.kv b` | 20px | 600 | 1.3 | 0 | `--ink-1` |
| `.src` / `.meta` / `.foot` | 12px | 400 | 1.65 | 0 | `--ink-3` |
| `.tag` | 12px | 500 | 1.3 | 0.01em | `--ink-2` |
| 微型标识（序号、`SRC`） | 10px | 600 | 1 | 0.08em | `--ink-3` |

对比现状：正文 12–14px → 15px（12px 中文在 2× 屏已是下限）；`.sub` 12px `#888` → 12px `--ink-3`；`.foot` 11px → 12px；`.card h2` 15px `#555` → 13px `--ink-2`（**降级标题、升级数字**，这是"重点突出"的第一手段）。

### 3.3 数字策略

- `.big`、`.kv b`、`.rank .num`、`.hist-tbl td` 全部加 `font-variant-numeric: tabular-nums; font-feature-settings:"tnum" 1`。现有 CSS 只给后两者加了，`.big` 漏了——这是"数字跳动、列不齐"的根因。
- **中文与数字混排**：数字与紧随的中文之间用 `margin-left:6px`（不用全角空格，避免朗读出"空格"）；数字与前面的中文之间用 `margin-right:2px`。
- `.big` 与 `.unit` 共用基线：`.unit{font-size:13px;font-weight:500;color:var(--ink-3);margin-left:8px;letter-spacing:0}`。

### 3.4 "89.1" 这类关键数字的处理（重点突出）

四层叠加，成本极低：

1. **尺度差**：46px vs 正文 15px ≈ 3.1×，vs 现状 34/14 = 2.4×。这是唯一靠"变大"就能解决的部分。
2. **上方一行 mono 眉标**：`10px/600/0.08em --ink-3`，内容 "GOLDSTEIN 指数 · 第45周"。它让数字有归属，不悬空。（实现位置：`flu_body_html`，`:1010`，未被冻结。）
3. **等宽数字 + 光学压缩字距**：`tabular-nums` + `-0.02em`，让 `89.1` 在 46px 下不散开。
4. **一条 24px × 3px 的品牌色短线**置于眉标左侧（`::before`），把视线钉在数字上。**不加底色块、不加渐变数字、不加发光。**

`.big.nodata`（"—"与"？"）：保持 **24px、不加粗、`--ink-3`**，并强制其下方出现虚线状态框。规则："缺测数字在物理尺寸上必须明显小于真实数值"，防止"未获取"在扫视中被误读成一个读数。

## 4. 布局与栅格

### 4.1 宽度上限：640px 确实太窄

640px 是**读散文的栏宽**，不是**读数据表的栏宽**。当前 6 张卡纵向叠在 640px 里，桌面 1440 屏上左右各 400px 空白，而卡内表格（`hist-tbl` min-width 340）和折线仍被压窄——这是"信息密度低"和"看不完"同时发生的根因。

新规格：

| 断点 | `.wrap` | 栅格 | 内边距 |
|---|---|---|---|
| ≥1024 | `max-width:1080px`（内容 1016） | **12 列，gap 20px，col 66.3px** | 0 32px |
| 720–1023 | 100% | 单列 | 0 24px |
| <720 | 100% | 单列 | 0 16px |

`max-width:min(1080px,100%)` + `box-sizing:border-box`，320px 下内容宽 288px。

### 4.2 卡片栅格：不改 DOM，不加 wrapper

**关键约束**：`#default-view` 的首个子元素必须是 `.banner`。`run_banner`（`:71`）在正常情况下返回**空字符串**（`:141-142`、`:153-154`），`banner_html`（`:1729`）也常为空——也就是说**大量状态下 `#default-view` 的首子元素其实是第一张 `.card`**。任何"新增 wrapper 包住卡片"或"按 `:first-child` 选 banner"的方案都会踩空。

正确做法：**直接对 `#default-view` 用 grid**，靠 class 而非位置：

```css
#default-view{display:grid;grid-template-columns:repeat(12,1fr);gap:20px;align-items:start}
#default-view > .banner{grid-column:1/-1}
#default-view > .card{grid-column:1/-1}          /* 默认整行，未匹配到的卡永远不塌 */
#default-view > .card.c5{grid-column:span 5}
#default-view > .card.c7{grid-column:span 7}
```

`.card.c5/.c7` 由 `_card()`（`:764`，**未冻结**）新增可选参数产出；`_slot_templates`（`:1621`）调用时不传，查询视图自动继承整行。

**放置方案（DOM 顺序不动，纯 CSS 布局）**：

| 行 | 卡（DOM 序） | span | 实宽 |
|---|---|---|---|
| 1 | `sc` 四川分级（hero） | 12 | 1016 |
| 2 | `flu_south` 南方片指数 | 5 | 412 |
| 2 | `hist_south` 历年同周 | 7 | 584 |
| 3 | `rank` 全国排行 | 5 | 412 |
| 3 | `trend` 三病原趋势 | 7 | 584 |
| 4 | `child` 儿童分龄 | 12（内部 2 列） | 1016 |

7+5/5+7/12 每行均满 12，**无网格空洞**；且各行跨度与 DOM 顺序一致，键盘 Tab 顺序（每张卡 `.src` 里有外链）与视觉顺序**完全一致**——这一点是硬要求，禁止用 `order`/`grid-row` 视觉重排。

第 2 行 `flu_south`（短）与 `hist_south`（高）会形成左列下方留白。`align-items:start` 保留自然高度差，**这是刻意的非对称节奏**，不是缺陷；用 `stretch` 拉高短卡只会得到一张底部空荡荡的大白块。

`#query-view`（`:1567`）不参与栅格：`#query-view > .card{grid-column:1/-1}`，保持单列阅读流。

### 4.3 卡内留白

`.card{padding:14px 20px 18px;border:1px solid var(--hair);border-radius:10px;box-shadow:0 1px 2px rgba(14,27,32,.04)}`

- 圆角 12 → **10px**：更硬朗，接近纸卡裁切。
- 阴影几乎取消，改由 1px 描边承担分层（阴影在 2× 屏上是"廉价 App"的强信号）。
- 上内边距 14px（给序号留位），下 18px（容纳 `.src` 的分隔线）。
- `<720` 时 padding 14px 16px。
- 长文段（`.adv`、`.foot`、`.hist-sub`）加 `max-width:68ch`，避免 1016px 宽下的长行。

## 5. 「现代科技元素」的具体做法

六条，按性价比排序。每条都给出实现位置、成本、风险。

**① 五段标尺（level rail）— 最值得做**
hero 内一行 5 段 6px 高色条（宽 100%，gap 3px），当前级实心、其余 22% 透明，段下 9px mono 罗马数字 Ⅴ Ⅳ Ⅲ Ⅱ Ⅰ（仅官方级号，不造名称）。
成本：中（改 `_sc_body`，`:1075`，未冻结；约 12 行 HTML + 15 行 CSS）。风险：低。**价值最高**——一眼看出"Ⅳ 在五档里的位置"，且天然不含合成分数（D14 合规），这正是"重点突出"与"诚实"能同时满足的唯一形态。

**② 图表 chrome 重着色（属性选择器）**
```css
svg text[fill="#999"]{fill:#56686F}
svg text[fill="#6b7280"]{fill:#56686F}
svg line[stroke="#e5e7eb"],svg line[stroke="#eef0f2"]{stroke:#EFF3F4}
svg line[stroke="#9ca3af"],svg line[stroke="#d1d5db"]{stroke:#9FB0B6}
svg rect[fill="#f3f4f6"]{fill:#F4F7F8}
```
成本：低（约 6 行纯 CSS，**零改动 Python**，因此 7 个冻结函数的字节断言不受影响）。
风险：中——与硬编码 hex 字符串耦合，若冻结函数日后改色，CSS 静默失效。**规避**：CSS 内写明注释 + 在回归套件加一条断言（断言产物 HTML 仍含这几个 hex 字符串）。只重着色 chrome，**绝不重着色数据系列**（`#c0392b`/`#7f8c8d`/`#8e44ad`/`#3a6ea5`），保留病种识别色的权威性。

**③ 卡片左上角 mono 序号**
`.card{position:relative;counter-increment:card}` + `.card::before{content:counter(card,decimal-leading-zero);position:absolute;top:14px;left:20px;font:600 10px/1 var(--mono);letter-spacing:.08em;color:var(--ink-3)}`，h2 相应 `padding-left:26px`。
成本：极低（纯 CSS 计数器，零 DOM 变更）。风险：低但需知两点——(a) `::before` 文本在 Chrome 会进入标题的可访问名，读屏读作"01 四川官方流感分级…"（可接受，也可整条删除换成一枚 10px 品牌色小方块）；(b) `textContent` 断言不受影响（伪元素不进 DOM）。

**④ hero 微网格底纹**
`repeating-linear-gradient(0deg,#0E1B20 0 1px,transparent 1px 24px)` + 90° 同参数，叠在 `linear-gradient(180deg,#F7FAFB,#FFF 160px)` 之上，整体 `opacity:.035`，只用于 hero 卡，`pointer-events:none`。
成本：低。风险：低——3.5% 不透明度在 1× 屏几乎不可见、2× 屏不会摩尔纹；**不要提高到 6% 以上**，否则变成 Excel 灰格。`@media print{display:none}`。

**⑤ 账本式表格**
`.rank` 行：`border-bottom:1px solid #EFF3F4`，表头 10px mono/0.08em/`--ink-3`，数值列 20px `tabular-nums` 右对齐、列头右对齐；`@media(hover:hover)` 下 `tr:hover{background:#F7FAFB}`。`hist-tbl` 同理，当前年行保留浅灰底但改为 `#F4F7F8` + 左侧 2px `--brand` 条（用位置而非颜色标记"这一行是本年"）。
成本：低。风险：低。

**⑥ 统一焦点环**
所有可交互元素（`#q`、`.q-btn`、`#q-list .q-item`、`.hist-scroll`、`.src a`）：`outline:2px solid var(--focus);outline-offset:2px`，替换现有的 1px/2px 混用。
成本：极低。风险：无。这是唯一一条"纯收益"的科技感——它同时是可达性要求。

### 明确反对

| 反对 | 为什么在这个项目会掉档 |
|---|---|
| **霓虹/外发光/glow** | 发光的语义是"此刻注意我"，而本页大量内容是"这是上周的存量数据"。把警告态视觉借给常态数据，等于欺骗。 |
| **玻璃拟态 `backdrop-filter`** | 需要背景有内容可透；白纸上无内容可透，只剩一层脏灰。且 file:// 与低端安卓 GPU 上会掉帧。 |
| **大面积深色渐变（含深色模式）** | 本轮**不做深色模式**：7 个冻结函数把 `#999`/`#6b7280`/`#e5e7eb` 当"浅底上的灰"硬编码，深色主题下这些标注会直接消失，而**没有权限改**。强行做会得到一张读不出轴的图。 |
| **数字滚动/入场动画/交错淡入** | 数据页的核心姿态是"我立刻告诉你数字"。延迟 400ms 才出现的 89.1，在用户眼里是"页面卡了"。 |
| **径向进度环/仪表盘弧** | 环形暗示"占满/百分比"。五级是序数不是比例，环会制造"Ⅳ 级 = 80%"的误读——与 D17"指数是相对强度、非百分位"直接冲突。**这是最容易犯的错，因为它在视觉上最"科技"。** |
| **彩虹渐变描边、粒子背景、视差** | 装饰密度超过信息密度后，读者会开始怀疑数据本身是否也被"装饰"过。 |
| **等高大卡片** | 六张卡信息量差 5 倍（hero 5 行 vs 历年卡 30 行）。强行等高只能靠灌留白。 |

## 6. 前后对比说明

拿 `base-desktop.png` 与改造后对比，用户会看到的三件事：

**① 从"一叠便签"变成"一张报告单"。**
现在：640px 窄栏里六张同样的白卡、同样的 12px 圆角、同样的软阴影，从上到下平均用力，看不出哪张最重要。改造后：1080px 宽、12 列栅格，hero 卡独占一行并带品牌竖条与五级标尺，右侧一列并排出现两张卡——**首屏（1440×900）能同时看到 四川分级 + 89.1 + 全国排行 + 历年同周 四块证据**，现在只能看到 1.5 块。竖向滚动距离预计减少约 40%。

**② 数字终于比标题大。**
现在卡标题 15px `#555`、数字 34px，主次只有 2.2 倍；且标题带灰度、数字纯黑，两者在扫视时互相争夺。改造后标题降到 13px `--ink-2` 并变成"眉标"，数字升到 46px 带等宽数字与上方 mono 标签——**视线路径从"读标题找重点"变成"数字自己跳出来"**。

**③ 状态第一次可读。**
现在所有状态都是同一种浅蓝 `.tag`（`#eef4ff`/`#3a6ea5`），"数据正常"和"官方分级未获取"长得一模一样，只能靠逐字阅读区分；`.sub` 的 `#888` 在 12px 下实测 ≈3.5:1，本就该改。改造后：正常=青点、待更新=琥珀左边条、失败=砖红左边条、**未获取=中性虚线框**，四态在余光里就能分开，且"未获取"没有任何一点像"安全"。

## 7. 实现风险清单

### A. 会撞回归断言 / 构建白名单

| # | 风险 | 规避 |
|---|---|---|
| A1 | **`PAGE_TPL` 是 `str.format` 模板**，CSS 内每个 `{` `}` 必须写成 `{{` `}}`。新增 CSS 若含单花括号，`str.format` 会抛 `KeyError` 或静默吃掉规则。 | 这是本轮**最高频的实操事故**。所有新增 CSS 一律双写花括号；构建前跑一次 `python -X utf8 src/build_site.py --local`。注意 `@media(hover:hover)`、`grid-template-columns:repeat(12,1fr)` 都含花括号。 |
| A2 | `.wrap` 640 → 1080 若有布局断言 | 已 grep 现有 validation 脚本未见 `640`/`max-width` 断言，但**须在实施前跑全套件确认**，不能以本文结论代替。用 `min(1080px,100%)` 保证小屏不溢出。 |
| A3 | `#default-view` 首子元素 `.banner` 断言 | **不加 wrapper**。grid 直接作用于 `#default-view`，`.banner{grid-column:1/-1}` 按 class 匹配。同时提醒：`run_banner` 在正常态返回 `""`（`:141-142`），"首子元素是 banner"只在有告警时成立——不要按 `:first-child` 写选择器。 |
| A4 | `.card`/`.big`/`.unit`/`.tag`/`.banner`/`#default-view` 存在性与嵌套不可变 | 只加修饰类（`.card.c5`/`.card.hero`），不改结构；`.big` 始终保持直接子元素，标尺作为**兄弟节点**插在其后。 |
| A5 | `#q` 必须 16px、`.q-btn` min-height 44px | 不动这两个数值。`.q-btn` 只改 border/background/radius/字重。 |
| A6 | 7 个冻结函数逐字节比对 | 全部视觉改动落在 CSS 与**未冻结**的 `_card`（`:764`）、`_sc_body`（`:1075`）、`flu_body_html`（`:1010`）、`_src_chip`/`_compute_chip`（`:1573`/`:1594`）内。修改前先 `git diff` 确认这 7 个函数体零改动。 |
| A7 | 白名单 `<script src`/`fetch(`/`@import`/`url(http` | 新 CSS 不得出现 `url(` 后跟 `http`；**`data:` 内联图片建议不用**——虽然 `url(data:...)` 能过校验，但它带来 base64 体积、且 `href` 校验器（`:1800`）对 `data:` 会走"内部链接"分支而报"不是本页锚点"。需要纹理一律用 `repeating-linear-gradient` 实现。 |
| A8 | 属性选择器依赖 hex 字符串 | 见 §5②，加注释 + 回归断言产物仍含 `#999`/`#6b7280`/`#e5e7eb`。 |
| A9 | `#query-view` 由 JS `cloneNode` 填充 | 不依赖 JS 加类；用 `#query-view > .card{grid-column:1/-1}` 兜底，克隆出的卡永远整行。 |
