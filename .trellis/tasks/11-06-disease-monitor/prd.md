> 本任务来自 grill（第 1–5 轮，2026-11-06）收敛的设计共识。术语见 `CONTEXT.md`，部署决策见 `docs/adr/0001-*.md`，完整设计见 `docs/design.md`。本 prd 只写需求/约束/验收，不写技术方案。
> 2026-11-06 自 InspirationStorm 迁移重建，项目根目录现为 D:\FluMonitor。

## 源需求（用户原话归纳）

用户现居成都、自述无开发经验，想做一个传染病数据监测工具，首要用途是**日常出行防护参考**，能查询其他省市，可随手分享给家人朋友。以一个流感指数面板为参考，但不确定做成什么形式——形式由 grill 确定为 GitHub Actions 自动更新网页 + 本地双触发。

## 已确认约束（D1–D18）

- D1–D13：见 CONTEXT.md（产品方向，不变）。
- **D14 首屏改分块证据页**（取消成都综合风险总分，修订 D3/D5）。
- **D15 数据边界对齐**（南方片只有流感数值；多病原数值为全国；南北/年龄仅前三名排序）。
- **D16 四川分级 = OCR + 多模态双通道**（一致才采信，缺/过期标待确认不默认绿）。
- **D17 历史只做同期对比曲线**（箭头仅表环比；不做百分位风险等级；南方片指数不混全国 FluNet）。
- **D18 前置数据可行性验证**（先验口径再批量回补；验收标准从"网页生成"改为"结论可追溯、证据不足显示未知"）。

## 任务地图（5 个可独立验证的子交付）

| 子任务 | 交付 | 依赖 |
|---|---|---|
| 11-06-data-feasibility | 口径对照表 + 可行性结论（D18 前置） | 无（起点） |
| 11-06-data-fetch | 抓取+解析+历史回补 → data/*.csv | data-feasibility |
| 11-06-compute-index | Goldstein 指数 + 同期对比 + 分块结论（不合成总分） | data-fetch |
| 11-06-build-site | CSV→分块证据页（极简→仪表盘） | compute-index |
| 11-06-deploy | 自定义 Actions 发布 Pages + 本地内联入口 | build-site |

依赖为线性顺序，写在各子任务 prd，不靠树结构表达。

## 跨子任务验收标准（父任务负责最终集成验证）

1. 先完成 data-feasibility 的可行性结论，再进 data-fetch 批量回补。
2. 从零 clean checkout 执行完整流程，产出含真实最新数据的分块证据页，data/*.csv 落盘且每行可追溯来源/口径。
3. 自定义 Actions 手动触发成功：抓数→算指数→构建→artifact 部署 Pages 可访问（不依赖 bot 提交触发构建）。
4. 本地 `run_local.bat` 双击产出数据内联的本地 HTML（file:// 离线可打开），不污染发布用主数据。
5. 各块结论来源/口径/数据状态可追溯，官方/推算、全国/南方片、数值/排序、周/月区分清晰；无合成总分。
6. 任一源临时失效/过期时页面显著提示，不静默显示旧数据、不显示缺数据为 0、官方分级缺不默认绿。
7. 历史回补按 data-feasibility 结论的可比范围执行，缺口有清单；南方片指数输入不混全国口径。
8. 仓库无个人隐私信息，发布前核过资料使用条件与发布范围。

## 明确不做（首期）

- 成都市级/区县级实时数据（公开数据不存在，不伪造）。
- 全 11 种病原首屏展示（仅架构预留）。
- 付费数据源、互联网平台数据作硬依赖。
- WorkBuddy 方案。
